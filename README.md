# Life & Health Planner

เว็บแอปสำหรับวางแผนชีวิตประจำวัน บันทึกกิจกรรมและเวลาที่ใช้จริง ติดตามการออกกำลังกาย โภชนาการ และข้อมูลร่างกาย พร้อมสรุปผลเพื่อช่วยให้ผู้ใช้เห็นรูปแบบการใช้ชีวิตและปรับแผนได้อย่างเหมาะสม

> **สถานะโครงการ:** เว็บแอปใช้งานเบื้องต้น อยู่ระหว่างพัฒนา  
> ระบบปัจจุบันเก็บข้อมูลในเบราว์เซอร์เครื่องนี้ ยังไม่มีบัญชีผู้ใช้หรือซิงก์ข้ามอุปกรณ์

## เป้าหมายของโครงการ

Life & Health Planner มีเป้าหมายเพื่อรวมการวางแผนและติดตามกิจกรรมที่เกี่ยวข้องกับชีวิตประจำวันไว้ในที่เดียว ได้แก่

- วางแผนตารางประจำวันและปรับเปลี่ยนเมื่อมีเหตุการณ์แทรก
- เปรียบเทียบเวลาที่วางแผนไว้กับเวลาที่ทำจริง
- บันทึกและติดตามการออกกำลังกายอย่างต่อเนื่อง
- บันทึกอาหารและประเมินพลังงานกับสารอาหารหลัก
- เก็บประวัติข้อมูลร่างกายและพฤติกรรมสุขภาพ
- สรุปข้อมูลเป็นรายสัปดาห์ รายเดือน รายปี และช่วงเวลาที่เลือก
- ใช้ข้อมูลที่บันทึกเพื่อสร้างคำแนะนำที่อธิบายเหตุผลได้

## ความสามารถของต้นแบบ

ส่วนติดต่อผู้ใช้ปัจจุบันเป็นเว็บแอปภาษาไทยแบบหน้าเดียว รองรับหน้าจอขนาดต่าง ๆ และมีส่วนหลักดังนี้

| ส่วน | ขอบเขตของต้นแบบ |
|---|---|
| ภาพรวม | แสดงข้อมูลสรุปของกิจกรรม |
| ตารางเวลา | จัดการรายการกิจกรรม |
| บันทึกเวลา | บันทึกเวลาที่ใช้กับกิจกรรม |
| โภชนาการ | บันทึกมื้ออาหารและข้อมูลโภชนาการ |
| ข้อมูลร่างกาย | บันทึกค่าร่างกาย |
| รายงาน | แสดงข้อมูลสรุปเบื้องต้น |

ความสามารถบางส่วนยังเป็นเพียงพื้นฐานและจะได้รับการพัฒนาต่อให้ครบตามข้อกำหนดในเอกสารหลัก

## เทคโนโลยี

- **Node.js** สำหรับรันแอปพลิเคชัน
- **Express 4** สำหรับให้บริการไฟล์เว็บแบบ Static และ health endpoint
- **HTML, CSS และ JavaScript** สำหรับส่วนติดต่อผู้ใช้
- **Browser localStorage** สำหรับจัดเก็บข้อมูลในเบราว์เซอร์เครื่องปัจจุบัน\n- **Node.js built-in test runner** สำหรับทดสอบ logic ที่แยกออกจาก UI

โครงการยึดแนวทางเริ่มจากเครื่องมือที่ไม่มีค่าใช้จ่ายก่อน และจะไม่เชื่อมต่อบริการแบบเสียเงินหรือส่งข้อมูลสุขภาพไปยังบริการภายนอกโดยไม่ได้รับอนุญาตจากเจ้าของข้อมูล

## เริ่มต้นใช้งาน

### สิ่งที่ต้องมี

- Node.js และ npm
- Git (หากต้องการ clone repository)

### ติดตั้งและเปิดใช้งาน

```bash
git clone https://github.com/tqcasper-prog/activity-log-app.git
cd activity-log-app
npm install
npm start
```

จากนั้นเปิดเบราว์เซอร์ไปที่:

```text
http://localhost:3000
```

หากต้องการตรวจสอบว่าเซิร์ฟเวอร์ตอบสนอง ให้เรียก:

```text
http://localhost:3000/health
```

คำสั่งเริ่มต้นอ้างอิงจากสคริปต์ใน `package.json` และ endpoint ที่กำหนดไว้ใน `server.js`

## โครงสร้างโปรเจกต์

```text
activity-log-app/
├── public/
```

## ข้อจำกัดที่ควรทราบ

ข้อจำกัดของต้นแบบปัจจุบันประกอบด้วย:

- ข้อมูลเก็บด้วย `localStorage` จึงผูกกับเบราว์เซอร์และอุปกรณ์ที่ใช้งาน
- ยังไม่มีบัญชีผู้ใช้ การซิงก์ข้ามอุปกรณ์ หรือระบบสำรองข้อมูลบนเซิร์ฟเวอร์
- การล้างข้อมูลเว็บไซต์หรือข้อมูลเบราว์เซอร์อาจทำให้ข้อมูลที่บันทึกไว้สูญหาย
- รายงานและการรวมข้อมูลตามช่วงเวลายังต้องพัฒนาให้คำนวณจากวันที่จริงอย่างครบถ้วน
- การจัดการช่วงเวลาและการตรวจสอบกิจกรรมที่ทับซ้อนกันยังต้องปรับปรุง
- ระบบติดตามความก้าวหน้าการออกกำลังกายและการปรับแผนตามผลจริงยังไม่สมบูรณ์
- ข้อมูลโภชนาการที่ผู้ใช้กรอกเป็นค่าประเมิน ไม่ควรถือเป็นค่าที่แม่นยำจากฐานข้อมูลอาหาร
- ยังไม่มีบัญชีผู้ใช้หรือการซิงก์ข้ามอุปกรณ์\n- การแก้ไขรายการบันทึกเวลา/อาหารย้อนหลังและการจัดการกิจกรรมประจำสัปดาห์ยังไม่ครบ\n- การตรวจจับเวลาบันทึกจริงที่ทับซ้อนกันยังไม่รองรับ\n- ยังต้องทดสอบการใช้งานจริงบนเบราว์เซอร์และอุปกรณ์หลายขนาด

โปรดสำรองข้อมูลสำคัญด้วยตนเอง และอย่าใช้ต้นแบบนี้เป็นเครื่องมือวินิจฉัยหรือทดแทนคำแนะนำจากบุคลากรทางการแพทย์

## แผนพัฒนาต่อ

การพัฒนาจะแบ่งเป็นช่วง เพื่อรักษาความสามารถที่ใช้งานได้และลดความเสี่ยงจากการเปลี่ยนแปลงขนาดใหญ่

1. **M0 — Audit & Stabilize:** ตรวจสอบระบบเดิมและทำให้พื้นฐานมั่นคง
2. **M1 — Data & Schedule Foundation:** วางโครงสร้างข้อมูลและระบบตารางเวลาให้รองรับวันที่และช่วงเวลาจริง
3. **M2 — Time Tracking & Reports:** บันทึกเวลาจริงและรายงานตามช่วงวันที่
4. **M3 — Exercise:** แผนออกกำลังกาย บันทึกผล และการเพิ่มระดับอย่างเหมาะสม
5. **M4 — Nutrition & Body Metrics:** บันทึกโภชนาการและประวัติข้อมูลร่างกาย
6. **M5 — Recommendations & Dashboard:** สรุปภาพรวมและคำแนะนำที่ตรวจสอบเหตุผลได้
7. **M6 — Data Portability & Cloud Readiness:** ส่งออก/นำเข้าข้อมูล และเตรียมความพร้อมสำหรับระบบคลาวด์
8. **M7 — Hardening & Release:** ทดสอบความปลอดภัย ความถูกต้อง และความพร้อมก่อนเผยแพร่

ลำดับและเกณฑ์การยอมรับของแต่ละช่วงให้ยึดตาม [เอกสารข้อกำหนดหลัก](docs/LIFE_HEALTH_PLANNER.md) และ [Master Prompt](docs/AI_BUILD_MASTER_PROMPT.md)

## ความเป็นส่วนตัวและความปลอดภัย

ข้อมูลกิจกรรม โภชนาการ และข้อมูลร่างกายอาจเป็นข้อมูลส่วนบุคคลที่ละเอียดอ่อน จึงต้องพัฒนาระบบโดยยึดหลักดังนี้:

- เก็บและประมวลผลเฉพาะข้อมูลที่จำเป็น
- ไม่ฝัง secret หรือ service-role key ไว้ในโค้ดฝั่งเบราว์เซอร์
- หากเพิ่มระบบคลาวด์ ต้องมีการยืนยันตัวตนและนโยบายควบคุมสิทธิ์ระดับข้อมูลที่เหมาะสม
- ต้องมีแนวทางส่งออกและลบข้อมูลของผู้ใช้
- การเชื่อมต่อ AI หรือบริการภายนอกต้องเป็นทางเลือกที่ผู้ใช้ยินยอมอย่างชัดเจน พร้อมแจ้งข้อมูลที่จะส่ง
- คำแนะนำด้านสุขภาพต้องไม่แสดงผลเสมือนเป็นการวินิจฉัยทางการแพทย์

## การทดสอบ

ก่อนเผยแพร่หรือเปลี่ยนแปลงระบบ ควรตรวจสอบอย่างน้อย:

- การเริ่มเซิร์ฟเวอร์และการเข้าถึงหน้าเว็บ
- การเพิ่ม แก้ไข และลบข้อมูลในแต่ละส่วน
- ความถูกต้องของการคำนวณเวลาและการรวมข้อมูลตามวันที่
- การคงอยู่ของข้อมูลหลังรีเฟรชหน้าเว็บ
- การแสดงผลบนมือถือและเดสก์ท็อป
- การจัดการกรณีข้อมูลไม่ครบหรือไม่ถูกต้อง

**หมายเหตุ:** `npm test` ใช้ Node.js built-in test runner และมี unit tests สำหรับ logic วันที่ เวลา การทับซ้อน และการรวมข้อมูลแล้ว แต่ยังไม่ครอบคลุมการทดสอบ end-to-end หรือการทดสอบหน้าจอจริง
